# Google workflow deployment and rehearsal

This folder contains deployable Apps Script V8 sources, a dependency-free business rules engine, fake Google-service tests, and a Python/JavaScript snapshot rehearsal bridge. No test connects to Google or sends email. Dry-run email is the default. Node 20+ and the repository's installed Python environment are needed for the tests.

```sh
npm test --prefix google
npm run build --prefix google
```

The generated `google/dist/` files are ignored. Copy `Core.gs`, `App.gs`, `Admin.html`, and `appsscript.json` into an Apps Script project **bound to a new private administration spreadsheet**. Enable the manifest's Gmail advanced service. The required OAuth scopes cover Sheets, Forms, private state/export/PDF Drive files, trigger creation, Gmail send only, external HTTPS PDF/Google identity validation, and signed-in user email. No Gmail read or delete permission is requested. Drive scope is necessary because administrators import existing exported folders and create separate public documents. Restrict project editors and workbook editors to the designated 2–3 PTA administrators. Do not publish the private workbook, state JSON, intake form responses, or export folder.

Refresh the workbook and open **PTA Lottery → Private administration**. Each button invokes a server allowlist; the active signed-in user must be in the event's configured `admins`. Blank identities and ordinary officers fail closed. Set up all administrators' access to the private spreadsheet and private state file, then each administrator authorizes the script. Do not use shared admin accounts. Two signoffs must come from distinct real signed-in administrators.

## Event configuration

Choose **Initialize new event** and supply the JSON argument array `[config, classes]`. The implementation refuses to overwrite an existing initialized event. `classes` contains stable `class_id` and `display_name`. Use a new bound project/workbook for another annual event. `config` must include:

- `event_id`, `game_target`, `food_target`, `admins` (at least two emails).
- `initial_deadline` (ISO timestamp with timezone), `grace_hours` (PTA-approved uniform duration; none is assumed).
- `retention_policy`, `sender_name`, `contact_verification_policy` documenting approved policies.
- `exception_approvers`, `publication_approvers`: explicit email arrays. Every listed approver must approve the same exception resolution or publication. Leaving authority unset blocks approval.
- `publication_audience`: either `{"viewers":["approved-recipient@example.org"]}` or explicitly approved `{"anyone_with_link":true}`. Both final Sheet and PDF receive view permission only. `officer_viewers` separately lists sanitized dashboard viewers.
- `identity_client_id`: Google Identity Services web client audience for external parent confirmation. Configure its authorized web origins for the deployed page, following Google Identity Services deployment requirements. Alternatively, an explicitly approved `confirmation_identity_policy: "trusted_workspace_session"` can use nonblank active-user email in a trusted Workspace domain; test the actual deployment's email visibility before use. An empty email is never replaced by the script owner's identity.

The sample fixture's policies and `.invalid` addresses are synthetic and are not board approval. Initial setup creates a private form, a class dropdown, three mandatory name/description/category proposal groups, private tabs, and form/hourly triggers. The form explains before submission that all three proposals are acceptable and no response within 48 hours of assignment email is automatically accepted.

The private event JSON is stored in a Drive file, avoiding ScriptProperties' 9 KB value limit. Properties contain only state/workbook/form identifiers and dry-run mode. Private workbook tabs are operator views of this state; editing their cells cannot authorize or alter the workflow. Material decisions are append-only event/history records inside the event state. **Form Responses** is append-only and never normalized in place. Apply the PTA retention policy to state, raw responses, contacts, old exports, tokens and audit backups. The script never invents or automatically executes a deletion policy.

## Intake through official import

1. Verify each class contact using the sidebar's roster verification controls and record evidence from the approved PTA roster. Dropdown selection and collected form email alone are insufficient.
2. Submit the shared form. Duplicate class submissions create versioned records and a review flag, never another class. Review each rank using explicit canonical booth ID, category, decision, and reason. A designated administrator selects the authoritative version; the previous version is preserved as superseded. Similarity suggestions in `LotteryCore.suggestions` are advisory; no name automatically merges booths.
3. Send correction requests with explicit per-request deadlines. Hourly triggers deliver notices/reminders, preserve versions, apply the configured uniform missing-submission grace period, and flag unresolved classes for PTA review. Freeze blocks unresolved correction requests, missing/unverified classes, rejected proposals and fewer than three distinct approved booth IDs.
4. Use **Check draft feasibility (nonofficial)** before signoff. A deterministic capacity-flow check enforces one class/booth and exact category targets without generating priority or an official allocation. Infeasibility blocks signoff while choices remain editable; **Invite all classes to voluntary revision** takes `[reason, correction_deadline]` and conservatively invites every potentially helpful class. Review voluntary revisions and rerun the check. First admin signs off, then the second signs off against exactly the same input digest. Input changes invalidate pending signoffs; **Reset pending approvals** requires renewed review. After freezing the event is immutable. Export the frozen folder; it contains only `classes.csv`, `approved_proposals.csv`, `config.json`, no contacts. Canonical UTF-8/LF CSV, sorted compact JSON and SHA-256 bytes match the Python loader.
5. Run the desktop's independent **nonofficial feasibility** check before a draw as well. Draft correction outreach never discloses others' proposals or promises priority. A frozen event needing policy or input changes must be abandoned and replaced through a new reviewed event, preserving the old one.
6. Use the desktop to commit once. Upload the complete output directory, including its `snapshot` child folder, into Drive. **Import committed output folder** takes its folder ID. Import validates exact filenames/manifest hashes, embedded snapshot and exact frozen bytes, audit hash, run/event IDs, three-choice edges/ranks/categories, exact quotas/uniqueness, deterministic priority seed/order, objective values, summary/report and two frozen approvals. Reimport of the identical run is harmless; another run or replacement cannot overwrite the original. Documented post-draw changes use exceptions. Google revalidates results but does not independently reoptimize OR-Tools objectives; desktop tests/verification cover optimization.

## Private confirmation and exception consent

Deploy the project as a web app **executing as the owner**, with access appropriate to the approved parent population. This is necessary so parents never receive private workbook/state permissions. Admin sidebar operations still authenticate `Session.getActiveUser()` independently. External parents authenticate with Google Identity Services. POST verifies Google's ID token through HTTPS `tokeninfo`, checking audience, issuer, expiration and verified email, then matches the token's bound class/run/email. A trusted Workspace Session identity is allowed only under the explicit policy above. Never use `getEffectiveUser()` as recipient identity. End-to-end GIS origins and Workspace account behavior require a real staging deployment; these cannot be proven offline.

Choose **Send class assignment** with `[class_id, "assignment"]`. Rehearsal returns a private mail preview without calling Gmail or assigning a sent timestamp/deadline. Use **Reset rehearsal sends** before live operation. Enable live mode only after the policy fields, identity setup and deployment URL are complete. Run a synthetic staging test first.

Each assignment email contains only that class's booth/category/rank and private confirmation link. Send intent is durably recorded as `SENDING` before Gmail is called. The Gmail advanced service supplies an actual message ID; receipt time starts the 48-hour deadline. An hourly reminder becomes eligible at 24 hours. Hourly scheduling can be late; state transitions enforce `now >= sent_at + 48h`, never a fabricated exact scheduler firing time. The link's POST must include both the random token and a verified matching Google identity. GET is read-only and reveals no class information. Only a SHA-256 token digest is retained. Tokens cannot cross classes/runs or replay. Three UUIDs supply token entropy; forwarded links alone are insufficient without the recipient's verified identity, but a compromised recipient account remains a PTA reconciliation matter.

A timely accept is `CONFIRMED`; timely decline opens an exception. No reply at 48 hours becomes `AUTO_ACCEPTED`. A late decline opens PTA review without undoing automatic acceptance. A crashed or quota-failed send remains `SENDING` and **cannot automatically retry**, because its delivery may be uncertain. Check Gmail Sent, then use **Reconcile uncertain send** with actual message ID/sent time and evidence, or evidence that nothing was sent. Only a proven unsent attempt is cleared for retry. Dry-run timestamps are never reused in production. Gmail/Apps Script daily quotas and trigger runtime limits vary by account; batch sends and monitor execution logs. A failure preserves earlier successful sends; resume unsent classes only after reconciling uncertain ones.

For withdrawals or other changes, **Open exception** takes `[type, affected_class_ids, reason]`; the original draw remains immutable. An administrator requests consent with `[exception_id, class_id, proposed_booth_id, explicit_deadline]`. The private link authenticates the affected recipient before recording consent/refusal; no reply is never consent. **Approve exception resolution** supplies the same full candidate roster and reason to every configured approver. Changes require consent for every affected/changed class, including assignments outside submitted choices, and exact category quotas/booth uniqueness remain mandatory. The history records the original roster, resulting version and approvals. No operation rerolls. Public approval remains blocked on open exceptions or unresolved confirmations.

## Sanitized publication

**Approve final Sheet and PDF** records configured approvals against a complete validated roster. Every class must have an explicit or automatic acceptance, no unresolved exceptions, one unique booth and exact category totals. Both separate sanitized artifacts use the same roster version and expose only class display name, canonical booth name and category. The PDF request explicitly uses letter paper. A prepared spreadsheet ID is persisted before PDF export, so PDF failures retry the same sheet. File IDs are persisted before sharing; publication is only marked complete after both artifacts receive the explicit read-only audience. Old versions remain intact; changing back to a historical roster still creates a new version. **Create sanitized officer dashboard** makes a separate read-only spreadsheet with class/status only. It never shares a hidden tab or private spreadsheet.

## What is validated offline

`npm test` exercises intake/version review, authorization failures, correction/grace blocking, snapshot bytes through the real Python loader, output tampering/idempotency, send-intent crash recovery, quota-failure retry protection, actual receipt deadlines, explicit/automatic/late responses, token replay/identity checks, consent/policy gates, publication versioning, sanitized columns, and actual adapter PDF-failure retry and read-only sharing using fakes.

`node google/scripts/rehearse.js prepare sample-data/google-intake.json OUTDIR` writes `OUTDIR/frozen` and `state.json`. After a real Python committed run exports that snapshot, `node google/scripts/rehearse.js complete STATE_JSON EXPORTED_FOLDER RESULT_DIR` validates the Python output and simulates private sends, explicit acceptance, decline, consented exception resolution, nonresponse autoaccept and approved sanitized publication. These paths use mock contacts and no Google service. The repository-wide rehearsal script automates this bridge.

Live deployment, account authorization, quota behavior, actual Gmail delivery, Google Identity Services origins, Drive access and physical PDF appearance still require staging validation by the real PTA administrators before production. No real Google accounts were connected during implementation.
